# Машулик

Уютный pixel-art симулятор маленького магазина комнатных растений. Браузерная игра на HTML5 Canvas и чистом JavaScript — без фреймворков, сборки и сервера.

> 🌿 Играть онлайн (GitHub Pages): **[ВСТАВИТЬ ССЫЛКУ, например `https://<логин>.github.io/<репозиторий>/mashulik/`]**

---

## Описание игры

Маше 21 год, и она наконец открыла собственный магазин растений — «Машулик». Каждый игровой день она поливает и удобряет растения, лечит их от вредителей, встречает покупателей, консультирует их, продаёт растения у кассы, предлагает горшки и грунт, заказывает новые поставки и читает отзывы.

Магазин растёт вместе с игроком: от пары деревянных стеллажей на 1 уровне до настоящего plant boutique с витриной редкостей, мраморными постаментами, гирляндами и золотой табличкой на 15 уровне.

**Цель:** достичь 15 уровня и получить награду **«МАШУЛИК — ЛУЧШИЙ МАГАЗИН РАСТЕНИЙ ГОДА»**. После награды можно продолжать играть.

## Основные механики

| Механика | Как работает |
|---|---|
| **Игровой день** | 09:00–19:00, ~4 минуты реального времени. Утро (подготовка, магазин закрыт) → открытие → день → вечер → отчёт. Пока открыто окно (диалог, карточка, каталог), время стоит — игра не торопит. |
| **Уход за растениями** | У каждого вида: здоровье, влажность, питание, свет. Состояния `HEALTHY / DRY / OVERWATERED / PESTS` видны прямо на спрайте (опущенные листья, желтизна, «точки»-вредители). Полив по мокрой земле — перелив и вред. |
| **Покупатели** | 10 архетипов + 6 постоянных клиентов. Входят через дверь (колокольчик), осматривают полки, подходят к Маше, ждут с индикатором терпения, идут к кассе. |
| **Консультация** | 24 реальные ситуации («северные окна и кот», «я убила кактус»). Игрок выбирает растение только из наличия. Иногда — второй вопрос (полив, свет, влажность, безопасность для питомцев, удобрения) или покупатель сам присмотрел растение. |
| **Цены** | У каждого растения есть закупочная, рекомендованная и цена «Машулика». Цена влияет на решение покупателя, но вероятности не показываются. |
| **Касса и допродажи** | Покупатель реально идёт к кассе, Маша подходит, предлагает грунт/горшок/удобрение, звучит касса, вылетают монетки и прибыль. |
| **Поставщик** | Компьютер в рабочей зоне. Деньги списываются сразу, коробки появляются у склада утром следующего дня. |
| **Экономика** | Баланс, выручка, себестоимость, прибыль, средний чек, расходы на закупки, списанные растения. |
| **Прогрессия** | XP за продажи, консультации, уход, задания, довольных покупателей. 15 уровней, на каждом что-то открывается, магазин визуально меняется. |
| **Отзывы и рейтинг** | Отзывы зависят от событий дня (ожидание, цена, качество совета). Общий рейтинг — скользящее среднее. |
| **Задания и достижения** | 3 ежедневных задания (XP + деньги) и 12 достижений. |
| **Сохранение** | `localStorage`, автосохранение после продажи, заказа, конца дня и нового уровня. |

## Управление

**Мышь / touch (основное):** click-to-move. Нажми на пол — Маша пойдёт туда. Нажми на растение, покупателя, кассу, компьютер, дверь склада или коробки — Маша подойдёт и только потом откроется окно взаимодействия.

**WASD / стрелки:** альтернативное движение (с коллизиями).

**Esc:** пауза / закрыть окно.

Игра работает на iPad (Pointer Events, адаптивное масштабирование, крупные кнопки).

## Используемые технологии

- HTML5
- CSS (пиксельные рамки, без препроцессоров)
- Canvas API — вся графика процедурная: `fillRect`, `beginPath/moveTo/lineTo/fill`, offscreen-буферы; `imageSmoothingEnabled = false`
- Vanilla JavaScript (ES6+: классы, наследование, стрелочные функции, деструктуризация, `Map`/`Set`, статические поля)
- `localStorage` + `JSON.stringify / JSON.parse`
- Web Audio API — все звуки и фоновая мелодия синтезируются, аудиофайлов нет
- Pointer Events

Никаких фреймворков, игровых движков, npm-зависимостей, сборки и backend.

### Основные классы

- **`Game`** — сердце игры. Игровой цикл на `requestAnimationFrame` с `update(deltaTime)` / `render()`; скорость не зависит от FPS. Машина состояний: `MAIN_MENU, INTRO, SHOP_MORNING, SHOP_OPEN, CUSTOMER_DIALOG, PLANT_INTERACTION, SUPPLIER, CHECKOUT, DAY_REPORT, PROFILE, ACHIEVEMENTS, SETTINGS, PAUSED, LEVEL_UP, FINAL_AWARD`. Модальные состояния останавливают время мира, поэтому переходы не конфликтуют.
- **`Entity → Character → Player / Customer`** — наследование там, где оно естественно: общий код движения по пути и анимации шага живёт в `Character`.
- **`CollisionSystem`** — прямоугольные коллизии «ступней» персонажа со стенами и мебелью. При движении с клавиатуры оси проверяются раздельно (персонаж скользит вдоль стеллажа). Для click-to-move — A* по сетке 4×4 px со сглаживанием пути.
- **`Renderer`** — статичный фон пререндерится один раз на уровень; мебель, растения и персонажи сортируются по Y (depth sorting): персонаж ниже объекта рисуется поверх, выше — объект перекрывает его. Освещение: утренний свет, солнечный луч из окна, вечерний multiply + тёплые лампы.
- **`Plant`** — данные вида + живое состояние; `tick(hours)` меняет влажность/питание/здоровье.
- **`Shop`** — перестраивает планировку при новом уровне (новые стеллажи, витрина, постаменты) и распределяет растения: редкие — в витрину, крупные — на пол, светолюбивые — к окну.
- **`ParticleSystem`** — пул из 360 переиспользуемых объектов, без аллокаций в кадре.

### Игровой цикл дня
```
утро: поставка → уход (полив / удобрение / осмотр) → цены → заказ
  → «Открыть магазин» → покупатели → консультация → касса → допродажа
  → 19:00 закрытие → отчёт дня + отзывы + задания → ночь (растения сохнут, поставка едет)
  → следующее утро
```

## Использование AI-помощника

**Задача:** «Проектирование игрового цикла симулятора магазина растений».

AI-помощник (Claude) использовался для проектирования и реализации связки систем, чтобы каждое действие игрока влияло на следующее:

```
уход за растениями → открытие магазина → покупатели → консультации
→ продажи → закупка → отчёт дня → следующий день
```

- состояние растений (уход утром) влияет на их ценность и решение покупателя;
- консультация и ответы на вопросы формируют удовлетворённость → отзыв → рейтинг;
- продажи уменьшают склад → игроку нужно заказывать поставку, которая приезжает только завтра;
- отчёт дня подводит итог экономики и заданий, а ночь меняет состояние растений.

### Принятое предложение

Принята архитектура с единым классом `Game`, машиной состояний и игровым циклом `requestAnimationFrame` + `deltaTime`, где:
- время мира идёт только в «живых» состояниях (`SHOP_MORNING`, `SHOP_OPEN`, `CHECKOUT`), а модальные окна его останавливают — игра остаётся спокойной;
- покупатель — конечный автомат (`enter → browse/look → approach → waitHelp → dialog → toCheckout → waitCheckout → paying → leave`);
- качество консультации считается как доля выполненных критериев запроса относительно лучшего варианта из наличия;
- растение резервируется при согласии покупателя, а продажа и прибыль фиксируются только у кассы;
- заказ поставщику оплачивается сразу, а товар превращается в коробки у склада на следующее утро.

### Способ проверки

Ручное прохождение полного игрового дня: утро → полив → открытие → обслуживание всех покупателей → заказ → отчёт → следующий день → разбор поставки → сохранение → перезагрузка страницы → «Продолжить».
